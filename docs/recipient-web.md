# 受取Web

Honoに静的シェル `/receive`・`/invitations` とメール認証完了画面 `/recipient-auth` を同居させています。`RECIPIENT_WEB_URL`をAPIと同じオリジンに設定する構成です。既存の設定値を自動で変更していません。別ドメインの既存受取Webを置き換える場合は、許可Originと送信URLを運用側で合わせてください。

## 操作

1. 通知リンクを開き、通知が届いたメールアドレスで確認メールを要求します。
2. 確認メールのリンクを開いて認証し、元の受取画面へ戻ります。元の画面が閉じた場合は最初の通知リンクを開き直します。
3. 「メール確認が済んだので続ける」でpreviewを取得します。送信者名・注意文・期限だけを表示します。
4. 死亡を別の手段で確認したチェックを自分で選択し、開封ボタンを押した場合だけreadを呼びます。
5. 辞退・通報は本文を開かず実行できます。最終確定前に戻ることもできます。

招待の事前承諾画面には死亡確認チェックや本文取得を置きません。承諾しただけでは開封同意を記録しません。

## 秘密情報と操作競合

- HTML/JS/CSSは固定内容。宛先、伝言の件名・本文、トークンをサーバーで埋め込みません。
- 閲覧トークンはURLフラグメントからメモリへ読み込み、history.replaceStateで直ちにURLから削除します。Cookie/Storage/解析へ保存しません。callbackURLも固定の `/recipient-auth` だけです。
- 必要なトークンはPOSTのJSON本文にだけ送ります。GETや認証完了ではreadを呼びません。ログインメールそのものの単回認証リンクは既存Better AuthのURL契約を維持し、callback画面へ閲覧トークンを引き継ぎません。
- 全応答no-store/no-referrer。CSPはスクリプト・CSS・通信をselfに限定し、iframe埋め込みを禁止。外部フォント・解析は使用しません。
- 本文と送信者名はtextContentで描画します。HTMLとして解釈しません。
- 二重操作を抑止し、自動再送しません。通信失敗時は状態確認を案内します。
- hidden/pagehide/popstate/BFCache復帰では本文を消去し、進行中処理を中断・世代番号で応答破棄します。チェックは復元しません。再読込時は通知リンクからやり直します。
- 既に利用者が見た、コピーした、スクリーンショットした内容の回収はできません。サーバーで失効後の取得を拒否します。

## 検証

`tests/recipient-web.test.ts`は配信するJavaScriptそのものをDOMモックで実行します。Better Authの実際の認証リンクとCookieを使い、未認証、previewの非開示、明示開封、旧注意文版、停止後、二重操作、遅延応答、辞退、戻る/再読込/BFCache、招待承諾との分離を検証します。新規テストフレームワークは追加していません。

`bun scripts/recipient-web-local.ts` → `bun scripts/recipient-web-smoke.ts`でループバック実HTTPの認証から停止後失効まで確認済み。メールはDB内キャプチャのみで外部送信しません。検証サーバーは停止すると全データを破棄し、認証リンクを標準出力へ記録しません。

この実行環境はブラウザー一覧が空で、in-app browserも利用不可でした。実ブラウザーの描画、CSPの実ブラウザー強制、Cookie・タブ・BFCacheのブラウザー差、iOS/Androidメールアプリとの往復、画面サイズ、VoiceOver/TalkBackは確認待ちです。DOMモックやHTTP試験でこの確認を代替したとは扱いません。
